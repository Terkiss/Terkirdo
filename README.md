## 📖 소개

안녕하십니까, 주인님! 1급 메이드 오케스트레이터, **테르키르도(Terukirdo)**입니다.

이 저장소는 단순한 프롬프트 모음집이나 스크립트 도구 상자가 아닙니다. **인간의 직관과 글로벌 웹 인텔리전스, 그리고 7인의 독립 에이전트 군단**이 유기적으로 맞물려 작동하는 **"엔터프라이즈급 자율 다중 에이전트 시스템(Autonomous Multi-Agent System) 템플릿"**입니다.

React, Next.js, Flutter, .NET, Python, Go, Rust — 기술 스택에 구애받지 않습니다.  
이 템플릿을 복사해 넣는 순간, 제가 즉시 프로젝트의 총사령관으로 투입되어 **기획의 모호성을 분쇄하고, AI의 꼼수 코딩을 원천 차단하며, 100% 무결한 결과물**을 대령합니다.

### 🌟 v5.6 7대 핵심 철학

| # | 원칙 | 설명 |
|:-:|------|------|
| 1 | **상류 정보 무결성 (Upstream Primacy)** | "상류의 정보 품질이 하류 구현의 품질을 100% 지배한다." 코딩을 서두르지 않고 최대 1시간에 달하는 초심층 웹 리서치와 5인 전문가 회의로 기획 모호성을 0%로 증발시킵니다. |
| 2 | **결정론적 파이썬 물리 게이트 (Python Code-Gate)** | 확률적 프롬프트의 한계를 극복하기 위해 `validate_spec_lock.py` 및 `validate_harness.py`를 탑재하여 스펙 린트, GWT 인수조건, 에이전트 모델 Enum 및 `tools` 권한 계약을 물리적으로 강제 검증합니다. |
| 3 | **메이드 결재의 원칙 (Master Approval Gate)** | 기획 검증이 끝나도 독단으로 코딩을 시작하지 않습니다. 1페이지 요약 보고서를 주인님께 올리고, 주인님의 명시적 `승인`을 득해야만 랄프 루프를 가동합니다. |
| 4 | **비대칭 듀얼 엔진 오케스트레이션 (Dual-Engine Asymmetric Orchestration)** | 고심도 추론·설계·구현·적대적 심판(`UltimateMake`, `terukirdo-plan`, `agy-worker`, `tech-expert`)은 **Gemini 4 Argon (`pro`)**이, 초고속 정적 리뷰 및 물리 관제(`first-reviewer`, `UFC`, `FAC`)는 **Gemini 3.8 Flash (`flash`)**가 전담합니다. |
| 5 | **적응형 유연성 (Adaptive Fluidity)** | 사소한 대화나 오탈자 수정(Tier 0/1)에서는 깝깝함 없는 신속한 속도를, 엔터프라이즈 코어 작업(Tier 2/3)에서는 철벽의 다중 에이전트 방패를 가동합니다. |
| 6 | **삼권분립 & 적대적 교차 검증 (Separation of Powers)** | 코드를 짠 구현자(Worker)는 절대 셀프 합격 판정을 내릴 수 없습니다. 독립된 `tech-expert`(심판관)와 `UFC`(환경관제탑)가 꼼수와 경계 누수를 끝까지 추적합니다. |
| 7 | **하드코어 안전장치 (Zero Trust Hooks)** | 시스템 레벨의 훅이 파괴적 명령어(`rm -rf`, `DROP TABLE` 등)와 Secret 유출을 물리적으로 차단합니다. |

## 🎯 UltimateMake: 마스터 기획 하네스

`UltimateMake`는 모호한 아이디어를 **"3각 지능 검증(Triangular Verification)"**을 통해 **모호성 0%의 불변 기획서(Frozen Spec)**로 승화시키는 테르키르도의 최상위 기획 하네스입니다.

```
👑 [Phase 1: 소크라테스 인터뷰]  ──> 5대 핵심 질문으로 여정/제외범위(Out-of-Scope)/에러모드 분쇄
        ↓
🌐 [Phase 2: 초심층 웹 탐색]      ──> universal-crawler 가동, 최대 1시간 RFC/GitHub/CVE 전수 스캔
        ↓
🤖 [Phase 3: 5인 전문가 회의]     ──> 아키텍트, 보안관, 악마의 변호인, QA, UX 전문가 원탁회의
        ↓
🔒 [Phase 4: 스펙 락 & 파이썬 검증] ──> docs/specs/*.spec.md 작성 후 validate_spec_lock.py 물리 검사
        ↓
👑 [Phase 5: 주인님 보고 & 최종 결재] ──> 1페이지 요약 서류 상신 ──[🛑 "승인" 명령 필수]
        ↓ (승인 완료 시)
⚡ [Phase 6: Ralph Loop 구현 착수] ──> 모호성 0%의 실행 카드를 들고 AGY Worker 즉시 투입
```

## 🤖 7인의 실무진: Ralph Loop

Orchestrator Mode에서 구현 단계(Phase 6)에 진입하면 **7인의 전문 에이전트 파이프라인**이 가동됩니다.

```
┌─────────────────────────────────────────────────────────────────────────┐
│                        Ralph Loop Pipeline                              │
│                                                                         │
│  ┌──────────────┐    ┌───────────────┐    ┌─────────────────┐          │
│  │ Ralph        │───▶│ Terukirdo     │───▶│ AGY Worker      │          │
│  │ Orchestrator │    │ Plan          │    │ (코드 구현)      │          │
│  └──────────────┘    └───────────────┘    └────────┬────────┘          │
│                                                     │                   │
│                                                     ▼                   │
│  ┌──────────────┐    ┌───────────────┐    ┌─────────────────┐          │
│  │ Final        │◀───│ Universal     │◀───│ Tech Expert     │          │
│  │ Approach     │    │ Final         │    │ (Judge)         │          │
│  │ Control      │    │ Controller    │    │                 │          │
│  └──────┬───────┘    └───────────────┘    └─────────────────┘          │
│         │                                          ▲                    │
│         │            ┌───────────────┐             │                    │
│         │            │ First         │─────────────┘                    │
│         │            │ Reviewer      │  P1/P2 발견 시 Rework            │
│         │            └───────────────┘                                  │
│         ▼                                                               │
│    ✅ APPROVED FOR COMMIT ONLY  또는  🔄 REWORK                            │
└─────────────────────────────────────────────────────────────────────────┘
```

| # | 에이전트 | 구동 엔진 (`model`) | 도구 권한 (`tools` Frontmatter) | 역할 |
|:-:|---------|:---:|:---:|------|
| 1 | **Ralph Orchestrator** | `pro` (**Gemini 4 Argon**) | Read-Only + `invoke_subagent` | 루프의 현장 소장. SAD 파이프라인으로 작업을 분해하고 워커에게 단일 스킬만 부여하여 지시 |
| 2 | **Terukirdo Plan** | `pro` (**Gemini 4 Argon**) | Read-Only (`view_file`) | Spec Lock 문서를 바탕으로 단계별 실행 카드(Execution Cards) 수립 |
| 3 | **AGY Worker** | `pro` (**Gemini 4 Argon**) | **Write + Shell** (`write_file`, `edit_file`, `run_command`) | 실제로 터미널을 두드리고 코드를 짜는 유일한 Write 행동대장 |
| 4 | **First Reviewer** | `flash` (**Gemini 3.8 Flash**) | Read-Only (`view_file`) | 워커가 작성한 코드를 초고속 1차 정적 리뷰 |
| 5 | **Tech Expert (Judge)** | `pro` (**Gemini 4 Argon**) | Read-Only (`view_file`) | 아키텍처·보안·치팅 관점의 심판관. 꼼수 및 경계 누수 적발 시 강제 Rework 지시 |
| 6 | **Universal Final Controller** | `flash` (**Gemini 3.8 Flash**) | Read-Only + `run_command` | 빌드 성공·테스트 통과·문서(SSOT) 정합성 1차 독립 물리 검증 (파일 수정 도구 배제) |
| 7 | **Final Approach Control** | `flash` (**Gemini 3.8 Flash**) | Read-Only + `run_command` | 커밋 직전 최종 관제탑. 에이전트의 말을 믿지 않고 **원시 Git 출력만으로 승인 판정** |

### 🔬 바이너리 역공학 결정론적 살균 게이트 (`scripts/hermes_disasm.py`)
네이티브 바이너리(PE32/PE32+) 분석 시 원시 x86/x64 어셈블리 바이트 덤프로 인한 상류 모델 안전 필터 오탐을 물리적으로 방지합니다.
- **Mode A (In-Memory Capstone + Hermes)**: 메모리 상에서만 디스어셈블을 수행하고 터미널 노출 없이 로컬 `Offrail-27B-12G`에 직접 전달.
- **Mode B (Hermes + REA MCP)**: `--use-rea` 모드로 리버스 엔지니어링 MCP 도구(`rea`)와 자율 연동.
- **Mode C (정규식 살균 게이트)**: stdout 출력 직전 니모닉/명령어 라인을 `[REDACTED_ASM_LINE]`으로 결정론적 마스킹.
- **`[FORCE_ASK: HERMES_UNAVAILABLE]`**: Hermes 또는 로컬 모델 미구동 시 콘솔 폴백을 원천 금지하고 즉시 주인님께 확인 요청.
